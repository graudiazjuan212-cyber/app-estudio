## 3. Lo que quiero (criterios de aceptación)
1. **Robustez**: `validatePack(x)` **nunca lanza** para ningún `unknown` (JSON de cualquier profundidad, ciclos, `BigInt`, funciones, `Symbol`, objetos con prototipo, getters que lanzan). Hay un límite de profundidad en `packConfig` (p. ej. `depthMax: 12`; un paquete legítimo llega a ~7). Si se supera o el input no se puede normalizar, devuelve `ok:false` con **un** error en español («El archivo está demasiado anidado…» / «El contenido no es JSON válido…») sin recorrer recursivamente. La comprobación de profundidad es **iterativa** (sin recursión).
2. **Propiedades heredadas / no JSON**: el input se normaliza a datos JSON puros antes de validar (p. ej. `JSON.parse(JSON.stringify(input))` dentro de `try`, tras la comprobación iterativa de profundidad), de modo que solo cuentan las propiedades propias enumerables. El `Pack` devuelto sale de ese dato normalizado. El `Object.create(item)` del punto 2.3 debe dar **error** (faltan campos), no `ok:true`.
3. **`extractMath`**: un backtick sin cierre es texto normal y se sigue buscando; las comprobaciones de `$` y de LaTeX siguen aplicándose al resto. Fences ```` ``` ```` sin cierre: igual (texto normal). Se mantiene: código cerrado se ignora, `\$` escapado, `$` sin cerrar → error.
4. **JSON Schema**: exportar en modo entrada (`io: 'input'`) para que `requiere` no sea obligatorio; añadir al nivel raíz un campo `description` (en español) que diga que existen reglas semánticas que solo comprueba la app (lista corta de las 8 reglas). Regenerar `docs/estudio-pack-1.schema.json` a mano con el mismo contenido que produciría el script (Codex no puede ejecutar node con red, pero sí `node scripts/export-schema.ts` si el sandbox lo permite; si no, escríbelo exactamente igual que lo generaría) — el test `schema.test.ts` comprueba la igualdad y Claude ejecutará `npm run schema:export` para confirmarlo.
5. **Mensajes** (todos en español de España, sin jerga):
   - `tipo` inválido: «`tipo` debe ser uno de: info, flashcard, test, multi, vf, ordenar, emparejar, huecos, error (has puesto «x»).»
   - `relaciona`/`explicacion`/`correccion` etc. no válidos para el tipo: «`relaciona` no se puede usar en una tarjeta `info` (solo en preguntas evaluables).» (mensaje específico para `info` + `relaciona`/`explicacion`; el resto de campos desconocidos mantiene la sugerencia por edición).
   - `id` con formato inválido: «El `id` solo puede tener minúsculas sin tildes, números, `-` y `_`, y empezar por letra o número.»
   - longitudes: distinguir por `issue.origin`: listas → «debe tener entre N y M elementos» (o «como mínimo N»/«como máximo M»); textos → «caracteres».
   - `opciones`/`pasos`/`pares`/`huecos`: con el nombre natural («opciones», «pasos», «pares», «huecos»).
6. Todos los tests anteriores siguen en verde salvo los que fijan mensajes cambiados (actualízalos con el texto nuevo escrito a mano, no calculado).
