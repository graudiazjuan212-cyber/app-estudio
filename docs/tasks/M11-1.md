Claude ejecuta `npm run check` y `npm run e2e`, devuelve fallos concretos y comitea. **La app ya está publicada:** no se cambia el esquema de IndexedDB ni el formato de copias (si algo lo exigiera, párate y descríbelo).

## 1. Contexto y por qué importa
Juan probó la app instalada en su Android (Chrome, PWA). «Exportar copia» y «Exportar progreso para Claude» fallan con «No se ha podido completar la operación. Tus datos se conservan.» Sin poder exportar no hay copia de seguridad ni progreso para Claude: es el fallo más grave posible. Además el mensaje oculta la causa real (un `catch` sin variable).

## 2. Estado verificado (Claude, `9f88deb`)
1. `src/ui/files.ts` `deliverFile`: crea `new File([json], fileName, { type: 'application/json' })`; si `canShareFile(navigator, file)` (`src/data/storage.ts:27`, que solo llama a `navigator.canShare({ files: [file] })`) → `navigator.share({ files: [file], title })`; si no → descarga con `<a download>`. En el `catch` de `share` solo se trata `AbortError` (cancelado); **cualquier otro error se relanza**.
2. `src/app/BackupPanel.tsx:20-26` (`operation`): `catch { setError('No se ha podido completar la operación. Tus datos se conservan.') }` → el error real se descarta. `src/app/ProgressExportButton.tsx:21` igual («No se ha podido exportar el progreso…»).
3. **Hipótesis de causa (no confirmada en el móvil):** Chrome para Android solo permite compartir archivos de ciertos tipos (imágenes, audio, vídeo, texto, PDF…); `application/json`/`.json` no está en la lista. `navigator.canShare({ files })` puede devolver `true` y aun así `navigator.share()` rechazar con `NotAllowedError: Permission denied`. También es posible `NotAllowedError` por perder la «activación del usuario» (el `share` se llama tras un `await` largo). En ambos casos el código actual relanza el error y se ve el mensaje genérico. **No hay ninguna ruta de «solo descargar».**
4. Restaurar: `BackupPanel` usa `<input type="file" accept=".json,application/json">`, `file.text()` y `restoreBackup`. Hay E2E de restauración con archivo preparado, pero **ninguno que restaure el archivo realmente generado por la descarga de «Exportar copia»**.

## 3. Lo que quiero
1. **Resultado de entrega con causa (`src/ui/files.ts`):** `deliverFile` deja de relanzar errores de `share`. Devuelve `{ status: 'shared' | 'downloaded' | 'cancelled', detail?: TechnicalDetail }`:
   - `canShare` falso → descarga directa (`downloaded`, sin detalle).
   - `share` OK → `shared`. `AbortError` → `cancelled`.
   - **Cualquier otro error de `share` (p. ej. `NotAllowedError`, `TypeError`, `DataError`) → descarga automática del mismo archivo (`downloaded`) con `detail` = detalle técnico del error de compartir.** Si además la descarga lanza, se lanza ese error con su detalle.
2. **Detalle técnico (`src/ui/technicalDetail.ts`, función pura, con tests):** `technicalDetail({ operation, error, fileName, fileType, size, canShare, userAgent, now })` → texto de varias líneas: `Operación: …`, `Error: <name>: <message>` (si no es `Error`, `String(error)`), `Archivo: <nombre> (<tipo>, <bytes> bytes)`, `canShare: sí|no|n/d`, `Navegador: <userAgent>`, `Hora: <ISO>`. **Nunca incluye contenido de la copia, ids, preguntas ni respuestas.** Constantes de textos en `src/config.ts`.
3. **UI de errores (`BackupPanel`, `ProgressExportButton`, y el panel de importación si comparte el patrón `operation`):** el `catch` conserva el error. Debajo del mensaje en español se muestra `<details><summary>Detalle técnico</summary><pre>…</pre></details>` (texto seleccionable, `role` apropiado, sin `any`) y un botón «Copiar detalle» (usa `navigator.clipboard.writeText`; si falla, el texto sigue seleccionable; mensaje de estado «Detalle copiado» / «No se ha podido copiar; selecciónalo a mano»). Cuando se descargó tras un fallo de compartir, mensaje de estado (no de error): «No se pudo abrir la hoja de compartir en este móvil; hemos descargado el archivo (busca <nombre> en Descargas).» más el detalle técnico desplegable.
4. **Botones «Descargar» sin compartir:** junto a «Exportar copia» añade «Descargar copia» y junto a «Exportar progreso para Claude» añade «Descargar progreso» (solo descarga con `<a download>` de un `Blob`; nunca llama a `share`). Tras generar el archivo con éxito, la copia se marca como hecha (`markBackupDone`) igual que hoy. Textos de ayuda: «Descargar guarda el archivo en la carpeta Descargas de tu móvil.»
5. **La descarga debe funcionar también tras un `await` largo** (sin depender de activación de usuario): crear el `<a>`, `click()`, retirar y liberar la URL con `setTimeout` como hoy.
6. **Restaurar la copia descargada:** comprueba por código que el flujo de restauración acepta exactamente el archivo que genera «Descargar copia» (extensión `.json`, nombre `estudio-copia-….json` o el actual) y, si el `accept` del `<input type="file">` pudiera ocultar el archivo en el selector de Android, amplíalo (`.json,application/json,text/plain,application/octet-stream`) manteniendo la validación por contenido (un archivo que no es una copia se rechaza igual, sin cambiar nada). Haz lo mismo con el input del importador de paquetes.
7. Textos: `README.md` sección 5 (copias) y 4 (progreso): explicar «Descargar copia» y que, si no se abre la hoja de compartir, se descarga solo; añadir a la tabla «Si algo falla» una fila «“No se pudo abrir la hoja de compartir”» → «El archivo se ha descargado: búscalo en Descargas». `docs/PRUEBA_MOVIL.md`: pasos para «Descargar copia», «Descargar progreso», restaurar el archivo descargado, y copiar el detalle técnico si algo falla.
