### `mastery.ts`
```ts
export type BlockStatus = 'pendiente' | 'en_curso' | 'dominado' | 'graduado';
export interface BlockState { blockId: string; status: BlockStatus; validDays: string[]; masteredOn: string | null; provisional: boolean; reviewDays: { day: string; clean: boolean }[]; locked: boolean }
export function blockState(block: CatalogBlock, catalog: Catalog, attempts: Attempt[], today: string): BlockState  // sin `locked` real: se rellena con lockStates

```
**Qué intentos cuentan** para un bloque: los de ítems evaluables del bloque **ahora** (por `catalog`, aunque en el intento figure otro `blockId`), con `itemGen === catalog.items.get(id).itemGen`, de ítems no archivados, y `tipo !== 'info'`. `today` = `studyDay` actual (el de «ahora»).

**Algoritmo exacto** (todo con los intentos de cada día `d`; días en orden ascendente):
- *Primer intento del día de un ítem* = el de menor `at` (empate: menor `attemptId`) ese `studyDay`.
- *Día válido* `d` ⇔ (nº de ítems cuyo primer intento del día es acierto) × 5 ≥ N × 4 **y** ningún intento de `d` en el bloque tiene `dontKnow` ni (`!correct` con `confidence === 'seguro'`). Con N = 0 (bloque sin evaluables) nunca hay días válidos: status `pendiente`. (Umbral = `studyConfig.masteryThresholdPercent`, 80; usa aritmética entera, sin decimales.)
- Se recorre cada día `d` con intentos del bloque, en orden:
  1. Si el bloque está **dominado antes de `d`** (`masteredOn < d`): si `d` tiene **algún** intento incorrecto (`!correct`, incluye `dontKnow` y flashcard `otra`) ⇒ **pérdida**: `validDays = []`, `masteredOn = null`, `reviewDays = []`, y **el propio día `d` no cuenta** como válido (decisión ADR-021). Si no hay fallo ⇒ `d` es **día de repaso**: `clean` ⇔ todos los intentos de `d` en el bloque son aciertos con `confidence === 'seguro'` (flashcard: `rating === 'facil'`); se añade a `reviewDays`.
  2. Si no está dominado: si `d` es válido ⇒ se añade a `validDays`; si `validDays.length >= 2` ⇒ `masteredOn = d` (el 2.º día válido). (Días no válidos no cambian nada: no restan.)
- Resultado: `pendiente` = ningún intento contado; `en_curso` = hay intentos y `validDays.length < 2`; `dominado` = `validDays.length >= 2`; `graduado` = dominado y los **3 últimos** elementos de `reviewDays` existen y los 3 son `clean`.
- `provisional = status ∈ {dominado, graduado} && masteredOn === today` (el 2.º día válido es hoy; se puede revocar con más intentos de hoy, y eso ocurre solo porque todo se recalcula desde los intentos). La graduación también es provisional si el 3.er día `clean` es hoy: se expresa con `provisional` igual (basta que `today` sea el último día de `reviewDays` y el estado sea `graduado`).
- *Bloqueado* (`locked`): `status === 'pendiente'` **y** algún id de `requiere` del bloque tiene status distinto de `dominado`/`graduado`. Un bloque con intentos (cualquier status ≠ pendiente) **nunca** está bloqueado.
- `chapterPercent` = `floor(100 × Σ peso de bloques dominado/graduado / Σ peso de todos los bloques con N > 0)`. Bloques con N = 0 se excluyen de numerador y denominador. Capítulo sin bloques con N > 0 ⇒ 0.

### `blindspots.ts`
```ts
export interface BlindSpot { itemId: string; since: string /* studyDay del fallo */ }
export function pendingBlindSpots(catalog: Catalog, attempts: Attempt[]): BlindSpot[]
```
Un **punto ciego** nace con un intento `!correct && !dontKnow && confidence === 'seguro'` (solo ítems evaluables no archivados, `itemGen` actual; las flashcards no generan). Se **resuelve** con un intento posterior del mismo ítem, en un `studyDay` **posterior** al del fallo, `correct` con `confidence` `bastante` o `seguro`. Un acierto con `duda`, o en el mismo día, no resuelve. Si tras resolverse hay otro fallo `seguro`, nace otro (nuevo `since`). Pendientes ordenados por `since` ascendente y después por `itemId`. Un fallo con `seguro` posterior a otro aún no resuelto **no** cambia el `since` original.

### `rebuild.ts`
```ts
export interface DerivedState { items: Map<string, ItemState>; blocks: Map<string, BlockState>; blindSpots: BlindSpot[]; skipped: { attemptId: string; reason: string }[] }
export function rebuildFromAttempts(attempts: Attempt[], catalog: Catalog, today: string): DerivedState
```
- Ordena una copia de los intentos por `at` y luego `attemptId`; omite (y lista en `skipped`, **sin lanzar**) los que no pasan `validateAttempt`, los de ítems que no están en el catálogo y los de `itemGen` distinto del actual; los ítems archivados **conservan** estado FSRS (por si reaparecen).
- FSRS por ítem aplicando `applyAttempt` en orden. `blocks` = `allBlockStates`. No muta las entradas.
- **Propiedad**: reproducir los intentos uno a uno con `applyAttempt` da, para cada ítem, exactamente el mismo `ItemState` que `rebuildFromAttempts` (cuando llegan en orden cronológico).
