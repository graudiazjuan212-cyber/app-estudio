### Esquema v1 (`schema.ts`)
Tablas (Dexie `stores`): 
- `subjects`: `id` → `{ id, nombre }`
- `chapters`: `id, subjectId` → `{ id, subjectId, numero, titulo, version }` (`version` = la versión **activa**)
- `blocks`: `id, chapterId, subjectId` → `{ id, subjectId, chapterId, titulo, peso, requiere: string[], order, archived }`
- `items`: `id, blockId, chapterId, subjectId, archived` → `{ id, subjectId, chapterId, blockId, tipo, itemGen, archived, relaciona, order, data: Item }`
- `packs`: `key, [subjectId+chapterId]` → `{ key: "<subjectId>|<chapterId>|<version>", subjectId, chapterId, version, importedAt, json: string }` (el texto original **tal cual** se importó)
- `attempts`: `attemptId, itemId, subjectId, studyDay, sessionId, at, [subjectId+studyDay]` → `Attempt` (solo se añade)
- `itemState`: `itemId` → `ItemState` (caché)
- `blockState`: `blockId` → `BlockState` + `{ subjectId }` (caché)
- `sessions`: `id, subjectId, startedAt` → `{ id, subjectId, kind: 'study' | 'review' | 'exam', chapterId: string | null, startedAt, endedAt: string | null, itemIds: string[], minutes: number, percentBefore: Record<string, number> /* chapterId → % al empezar */, result: { correct: number; total: number } | null }`
- `settings`: `key` → `{ key, value: unknown }`
- `snapshots`: `++id` → `{ id?, createdAt, reason: string, json: string }` (lo usa M3-2)
- `meta`: `key` → `{ key, value: unknown }` (`schemaVersion`, `schedulerVersion`, `lastBackupAt`)
`studyVersions: DbVersion[]` = `[{ version: 1, stores, upgrade?: (tx) => Promise<void> }]`. Un helper `defineDb(name, versions)` crea la instancia Dexie con todas las versiones declaradas (los tests pasan versiones extra).

### Apertura segura (`open.ts`) — ADR-013
```ts
export interface OpenHandlers { onVersionChange?: () => void; onBlocked?: () => void }
export type OpenResult =
  | { ok: true; db: StudyDb }
  | { ok: false; reason: 'version-newer' | 'blocked' | 'migration-failed' | 'unavailable'; message: string };
export async function openStudyDb(name: string, handlers?: OpenHandlers, versions?: DbVersion[]): Promise<OpenResult>
```
- **Copia previa automática**: antes de migrar, si la BD existe con una versión **menor** que la última de `versions`, se vuelcan **todas** sus tablas (JSON) a una BD aparte `${name}-premigration-v${from}` (un registro `{ key: 'dump', json }`; se conservan las `premigrationKeep` más recientes). Se abre la BD existente en modo dinámico (Dexie sin esquema) para leerla. Si la copia falla ⇒ **no se migra**, `ok:false, reason: 'migration-failed'`, BD sin tocar.
- Si la migración (`upgrade`) lanza ⇒ IndexedDB deshace la transacción: `ok:false, reason: 'migration-failed'`, la BD **sigue en la versión anterior con sus datos** (probar).
- Código más antiguo que la BD (Dexie `VersionError`) ⇒ `ok:false, reason: 'version-newer'`, mensaje «Recarga para actualizar»; **no escribe nada**.
- `versionchange` (otra pestaña abre una versión mayor) ⇒ la conexión se **cierra** y se llama `handlers.onVersionChange`. Evento `blocked` ⇒ `handlers.onBlocked` (y la apertura espera; si hay un tiempo límite configurable `dataConfig.blockedTimeoutMs` (por defecto 8000) ⇒ `ok:false, reason:'blocked'`).
- IndexedDB no disponible (lanzar al abrir) ⇒ `ok:false, reason:'unavailable'`.
- Registra `meta.schemaVersion` y `meta.schedulerVersion` (de `studyConfig`) al crear la BD.

### Catálogo desde la BD (`catalog.ts`)
`loadCatalog(db, subjectId?: string): Promise<Catalog>` construye el `Catalog` de M2-2 a partir de `items`/`blocks`/`chapters` (incluidos archivados, con `archived: true`). Usa **una** transacción de lectura.

### Importación (`importPack.ts`) — ADR-011
```ts
export interface ImportContext { now: string; tz: string; confirmOlder?: boolean }
export type ImportResult =
  | { status: 'rejected'; errors: PackError[] }
  | { status: 'already-imported' }
  | { status: 'needs-confirmation'; reason: 'older-version'; current: number; incoming: number }
  | { status: 'imported'; warnings: PackWarning[]; diff: PackDiff }
export async function importPackText(db: StudyDb, text: string, ctx: ImportContext): Promise<ImportResult>
```
1. `validatePackText` → si falla, `rejected` con esos errores. **No se toca la BD.**
2. Comprobaciones contra la BD (dentro de la misma transacción de escritura, para evitar carreras): cualquier `id` de ítem, bloque o capítulo del paquete que **ya exista en otra asignatura**, o un `capitulo.id` ya existente con otra asignatura ⇒ `rejected` con error en español que nombre el id y la otra asignatura («El id `x` ya lo usa la asignatura `y`.»).
3. Versión: si ya hay paquete para ese capítulo: igual versión y **mismo contenido normalizado** ⇒ `already-imported`; igual versión y **contenido distinto** ⇒ `rejected` («Ya existe la versión N de este capítulo con otro contenido; sube la versión.»); versión menor ⇒ `needs-confirmation` salvo `ctx.confirmOlder === true` (entonces se importa y esa versión pasa a ser la activa).
4. Si se importa: **una sola transacción Dexie** (`rw` sobre subjects, chapters, blocks, items, packs, attempts(solo lectura), itemState, blockState, meta) que: guarda el JSON original en `packs`; inserta/actualiza asignatura y capítulo (`version` = la importada); actualiza bloques (`order`; los que ya no están ⇒ `archived: true`; los que reaparecen ⇒ `false`); ítems: **nuevos** ⇒ `itemGen: 1`; **mismo id y tipo** ⇒ conserva `itemGen`, actualiza `data`, `blockId`, `order`; **mismo id, otro tipo** ⇒ `itemGen + 1` y **borra su `itemState`** (el historial en `attempts` se conserva); **desaparecidos** ⇒ `archived: true` (su `itemState` se **conserva**); **reaparecidos** ⇒ `archived: false`. Después recalcula las cachés del capítulo (`itemState` por reconstrucción de los ítems afectados, `blockState` de todos los bloques de la asignatura) **dentro de la misma transacción**.
5. Si cualquier paso lanza (incluida cuota) ⇒ la transacción se aborta, **no queda nada a medias** y la función **rechaza la promesa** con el error (no devuelve `imported`).
6. No muta el texto ni el paquete.

### Registro de intentos (`attempts.ts`) — ADR-003
```ts
export type RecordResult = { status: 'saved' | 'duplicate'; blockState: BlockState | null };
export async function recordAttempt(db: StudyDb, attempt: Attempt, ctx: { now: string; tz: string }): Promise<RecordResult>
```
Una transacción `rw` (attempts, itemState, blockState, lectura de items/blocks/chapters): valida con `validateAttempt` (si hay problemas ⇒ **rechaza** la promesa, no guarda nada); si ya existe `attemptId` ⇒ `duplicate` sin cambios (idempotente); si no ⇒ añade el intento, actualiza `itemState` con `applyAttempt` (si `needsRebuild`, reconstruye **ese ítem** con todos sus intentos de la generación actual ordenados), recalcula el `blockState` del bloque del intento (con `today = studyDay(ctx.now, ctx.tz)`) y devuelve el estado. Si el ítem no existe en `items` o su `itemGen` no coincide con el actual ⇒ rechaza (no guarda). Si falla cualquier escritura ⇒ nada guardado y la promesa rechaza (la UI mantiene la respuesta pendiente, ADR-003).

### Reconstrucción de cachés (`cache.ts`)
`rebuildCache(db, ctx: { now: string; tz: string }): Promise<{ items: number; blocks: number; skipped: number }>` — carga catálogo y **todos** los intentos, llama `rebuildFromAttempts`, vacía y reescribe `itemState` y `blockState` en **una** transacción. Los `skipped` se cuentan, no se borran.

### Sesiones (`sessions.ts`)
`startSession(db, row: Omit<SessionRow,'endedAt'|'result'>): Promise<void>` (inserta; `id` repetido ⇒ rechaza sin cambiar nada), `finishSession(db, id, endedAt: string, result: {correct:number,total:number} | null): Promise<void>` (idempotente: si ya tiene `endedAt`, no lo cambia), `listOpenSessions(db, subjectId): Promise<SessionRow[]>` (sin `endedAt`, más reciente primero) y `sessionAttempts(db, sessionId): Promise<Attempt[]>` (por `sessionId`, ordenados por `at` y `attemptId`). Tests: ida y vuelta, `id` repetido, `finishSession` dos veces, sesión inexistente ⇒ rechaza.
