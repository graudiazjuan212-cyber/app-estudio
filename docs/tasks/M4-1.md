## 3. Lo que quiero

### `src/domain/render/richtext.ts` (puro, sin React ni DOM, sin acceder a `window`)
```ts
export function renderRich(text: string): string        // HTML de bloque (<p>, <pre>, <ul>…)
export function renderRichInline(text: string): string   // HTML en línea, sin <p> (para opciones, pasos, botones)
export function richCacheSize(): number                  // solo para tests
```
- `markdown-it` creado **perezosamente** (función, no al importar) con `{ html: false, linkify: false, typographer: false, breaks: false }`. HTML escrito en el texto sale **escapado** como texto. Los enlaces `javascript:`, `vbscript:` y `data:` (salvo imágenes `data:image/png|gif|jpeg|webp`) no se convierten en enlaces (comportamiento por defecto de `validateLink`; **no lo relajes**).
- Regla propia para fórmulas, coherente con `extractMath`: `$…$` en línea → `katex.renderToString(src, { throwOnError: false, displayMode: false, output: 'htmlAndMathml' })`; `$$…$$` (puede ocupar varias líneas) → `displayMode: true`; `\$` sale como `$` literal; un `$` sin cerrar sale literal (no lanza); dentro de código en línea y bloques de código **no** se interpretan fórmulas. Una fórmula inválida produce el span `katex-error` de KaTeX (nunca lanza ni deja la pantalla en blanco).
- Salida **memorizada** por texto y modo (bloque/línea) con un mapa acotado a `renderConfig.cacheMax` (500) entradas (descarta la más antigua al llenarse). `renderRich('')` y solo espacios ⇒ `''`.
- Constantes en `src/config.ts` (`renderConfig`). Nunca lanza para ningún `string`.

### `src/domain/render/order.ts`
```ts
export function fnv1a32(text: string): number                              // hash FNV-1a de 32 bits sin signo
export function seedFor(...parts: (string | number)[]): number             // fnv1a32(parts.join('|'))
export function displayOrder(length: number, seed: number, opts?: { avoidIdentity?: boolean }): number[]
```
`displayOrder` devuelve una **permutación** de `0..length-1` usando `shuffle` de M2-3 (`displayOrder[k]` = índice original que se muestra en la posición `k`). Con `avoidIdentity: true` y `length ≥ 2` **nunca** devuelve la identidad (reintenta con `seed+1`, `seed+2`… hasta 10 veces y después rota una posición). `length ≤ 1` ⇒ `[0]` o `[]`. Determinista. Longitud negativa o no entera ⇒ lanza `RangeError`.

### `src/ui/RichText.tsx` y estilos
`<RichText text inline? className? />` usa `renderRich`/`renderRichInline` con `dangerouslySetInnerHTML` (único sitio permitido; comentario que explique por qué es seguro: `html: false` + KaTeX). Importa `katex/dist/katex.min.css` **una vez** en `src/main.tsx` (Vite empaqueta fuentes; M7 las precarga). Estilos en `src/ui/RichText.module.css`: bloques `pre` con **scroll horizontal**, fuente monoespaciada, sangría respetada (`white-space: pre`), `.katex-display` con scroll horizontal, `table` con scroll, imágenes `max-width: 100%`, colores con variables CSS existentes (claro/oscuro), `.katex-error` en color de error legible (contraste AA).

**`renderRich` (Vitest, entorno node)** — entradas → salida esperada (igualdad exacta salvo donde se indica «contiene»):
| # | Entrada | Esperado |
|---|---|---|

Además: `renderRichInline('**a** $x$')` no contiene `<p>`; dos llamadas iguales devuelven la **misma** cadena; tras 600 textos distintos `richCacheSize() <= 500`; una cadena de 100 000 caracteres no lanza; cadenas con caracteres especiales (`\u0000`, emoji, `$$$$`) no lanzan.

**`order`**: `fnv1a32('') = 2166136261`, `fnv1a32('a') = 3826002220`, `fnv1a32('foobar') = 3214735720` (vectores FNV-1a conocidos); `seedFor('a', 1)` = `fnv1a32('a|1')`; `displayOrder(5, 7)` es permutación de 0–4 y **igual** en dos llamadas; semillas 1 y 2 con longitud 8 dan órdenes distintos; `length` 0 ⇒ `[]`, 1 ⇒ `[0]`; con `avoidIdentity` y longitudes 2–8, para las semillas 0–199 **nunca** es la identidad; longitud `-1`, `2.5`, `NaN` ⇒ lanza `RangeError`; la entrada de `shuffle` no se muta.
