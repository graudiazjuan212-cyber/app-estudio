## 3. Lo que quiero

### Contrato del componente de pregunta (`src/ui/question/`)
```ts
export type Confidence = 'duda' | 'bastante' | 'seguro';
export type Submission =
  | { kind: 'answer'; answer: Answer; confidence: Confidence }         // tipos con confianza
  | { kind: 'dontKnow' }                                               // «No lo sé»
  | { kind: 'flashcard'; rating: FlashRating }                         // autoevaluación
  | { kind: 'seen' };                                                  // info: «Entendido»
export interface QuestionFeedback { correct: boolean; chosen: ChosenInfo }   // lo calcula el PADRE con grade(); ver abajo
export interface QuestionProps {
  item: Item; seed: number;                // seed estable (p. ej. seedFor(attemptId))
  onSubmit: (s: Submission) => Promise<void>;   // el padre guarda y, si va bien, pasa `feedback`
  feedback: QuestionFeedback | null;       // null = aún sin comprobar
  error: string | null;                    // error de guardado: se muestra con «Reintentar»
  onNext: () => void;
}
```
- `QuestionCard` (`QuestionCard.tsx`) elige el componente por `item.tipo` y gestiona el estado de envío: al pulsar «Comprobar» (o «No lo sé», o una calificación) **desactiva todos los botones inmediatamente** (un doble toque no envía dos veces) y llama a `onSubmit` **una sola vez**; si `onSubmit` rechaza, muestra `error` con un botón «Reintentar» que reenvía **la misma** `Submission`; **el feedback solo aparece cuando el padre pasa `feedback`** (ADR-003: nada de feedback antes de guardar). Tras el feedback: botón «Siguiente» (`onNext`).
- Un componente por tipo: `InfoCard`, `FlashCard`, `TestQuestion`, `MultiQuestion`, `TrueFalseQuestion`, `OrderQuestion`, `MatchQuestion`, `GapQuestion`, `ErrorStepQuestion` (cada uno ≤ 150 líneas). Todos reciben el mismo contrato interno (`item`, `seed`, `disabled`, `feedback`, `onChange(answer | null)`), y la confianza/«Comprobar»/«No lo sé» los pone `QuestionCard` (**no** se duplica en cada tipo).
- **Confianza**: tres botones tipo radio «Duda», «Bastante seguro», «Seguro» (un `role="radiogroup"` con etiqueta «¿Cuánta seguridad tienes?»), obligatorios **antes** de «Comprobar» (el botón está desactivado hasta que haya respuesta completa y confianza). Los tipos `flashcard` e `info` **no** muestran confianza.
- «No lo sé» siempre visible mientras no haya feedback (envía `{ kind: 'dontKnow' }`).
- **Orden y barajado**: las opciones/pasos/columnas se muestran con `displayOrder(n, seed, { avoidIdentity: true para ordenar })`; **todas las respuestas usan índices del orden original del paquete** (contrato de `grade`). El componente traduce posición visible → índice original.

### Interacción por tipo (ADR-007, solo toques)
- `test`: radiogroup de opciones (texto con `RichText inline`).
- `multi`: grupo de casillas (checkbox) con texto «Marca todas las correctas».
- `vf`: dos botones grandes «Verdadero» / «Falso».
- `ordenar`: lista de pasos barajados; tocar un paso lo coloca en la lista «Tu orden» (numerada); tocar uno colocado lo devuelve; botón «Vaciar». La respuesta está completa cuando están todos colocados.
- `emparejar`: dos columnas (izquierda en orden del paquete, derecha barajada); tocar uno de la izquierda y luego uno de la derecha crea el par (mismo color/numeral **y** etiqueta «Par 1»); tocar un par lo deshace. Completa cuando hay `n` pares.
- `huecos`: el enunciado muestra los marcadores `{{n}}` como «[n]» en negrita (sustitución en el texto antes de `RichText`) y debajo, para cada hueco, un radiogroup «Hueco n» con sus opciones barajadas.
- `error`: los pasos como botones de selección única numerados («Paso 1», …); el elegido es el que se considera incorrecto.
- `flashcard`: «Mostrar respuesta» revela el reverso y aparecen 4 botones: «Otra vez», «Difícil», «Bien», «Fácil» (cada uno envía `{ kind: 'flashcard', rating }`; no hay «Comprobar» ni confianza).
- `info`: título + cuerpo y botón «Entendido» (`{ kind: 'seen' }`).

### Feedback (cuando llega `feedback`)
Banner con `role="status"` y `aria-live="polite"`: «Correcto» (icono ✓) o «Incorrecto» (icono ✗), **texto + icono + color** (nunca solo color). Debajo: la `explicacion` (RichText) si existe; en `test`/`multi`/`huecos`, cada opción elegida incorrecta muestra su `feedback`; las opciones se marcan «Correcta»/«Incorrecta»/«Tu elección» con texto (no solo color). `flashcard`: tras calificar no hay «Correcto/Incorrecto» sino «Anotado» y el botón «Siguiente». El foco se mueve al banner al aparecer (para lector de pantalla).

### Accesibilidad y diseño móvil
Objetivos táctiles ≥ 44×44 px (CSS `min-height: 44px; min-width: 44px`); contraste AA en claro y oscuro (usa variables de `global.css`, ampliándolas si hace falta); orden de tabulación lógico; etiquetas accesibles; `prefers-reduced-motion` respetado (animaciones breves ≤ 150 ms y desactivadas con esa preferencia); sin sonidos. Estilos con CSS Modules (`src/ui/question/*.module.css`).
