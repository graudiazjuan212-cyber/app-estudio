## 3. Lo que quiero

### Capa de servicios en `src/data/` (cada archivo ≤ 300 líneas; importan dominio, **nunca** React ni `ui`)
- **`settings.ts`**: `interface Settings { sessionMinutes: 5 | 10 | 15; dailyGoalMinutes: 5 | 10 | 15; theme: 'system' | 'light' | 'dark' }`; defaults de `studyConfig` (sesión 10, objetivo 10, tema `system`). `getSettings(db): Promise<Settings>` (un valor guardado inválido o ausente cae al valor por defecto **sin lanzar**), `setSetting<K extends keyof Settings>(db, key: K, value: Settings[K]): Promise<void>` (valida; valor no permitido ⇒ rechaza sin escribir).
- **`views.ts`** (solo lectura, una transacción de lectura cada una):
  - `getHomeView(db, ctx: DataContext): Promise<HomeView>` con `{ subjects: { id, nombre, percent, dueToday, lastStudyDay: string | null }[]; streak: number; secondsToday: number; dailyGoalMinutes: number; goalReached: boolean; backupReminder: boolean; openSession: { id, subjectId, kind } | null; hasData: boolean }`. `percent` global de la asignatura = `floor(100 × Σ pesos de bloques dominado/graduado / Σ pesos de bloques con evaluables)` sobre **todos** sus capítulos; `dueToday` = nº de ítems evaluables, no archivados, con `ItemState` y `isDue(state, now, tz)`, no respondidos hoy; `lastStudyDay` = mayor `studyDay` de sus intentos (índice `[subjectId+studyDay]`); `streak` con `currentStreak` sobre los `studyDay` de **todos** los intentos; `backupReminder` = `backupReminderDue(lastBackup, now, hasAttempts)`; `openSession` = la sesión abierta más reciente de cualquier asignatura.
  - `getSubjectView(db, subjectId, ctx): Promise<SubjectView | null>` (`null` si no existe) con `{ id, nombre, percent, chapters: { id, numero, titulo, percent, hasEvaluables: boolean, blocks: { id, titulo, peso, status, locked, evaluables: number, requiere: string[] }[] }[] }`, capítulos ordenados por `numero` y bloques por `order`; bloques archivados **no** aparecen.
- **`study.ts`** (sesiones):
  - `startStudySession(db, input: { sessionId: string; subjectId: string; kind: 'study' | 'review' | 'exam'; chapterId: string | null; minutes: number; seed: number }, ctx): Promise<{ status: 'started'; sessionId: string } | { status: 'empty'; message: string } | { status: 'error'; message: string }>`. `study`: `buildSession` sobre el catálogo completo de la asignatura (estado derivado = `rebuildFromAttempts` de **todos** los intentos de la asignatura; no leas cachés, así es siempre coherente). `review` (Repasar capítulo): `buildSession` sobre un **catálogo filtrado** a ese capítulo (sus bloques e ítems; ítems y bloques de otros capítulos fuera). `exam`: `buildChapterExam` (los ítems en el orden devuelto). Si el plan queda **vacío** ⇒ `{ status: 'empty' }` con un mensaje en español («Hoy no queda nada pendiente en esta asignatura.» / «Este capítulo no tiene preguntas.») y **no** se crea sesión. Si crea, guarda `SessionRow` con `itemIds`, `minutes`, `percentBefore` (% de cada capítulo de la asignatura, calculado antes de empezar) y `kind`. Cualquier excepción del dominio o de la BD ⇒ `{ status: 'error', message }` (nunca lanza al llamador). `sessionId` repetido ⇒ `error` sin cambios.
  - `loadSessionRun(db, sessionId): Promise<SessionRun | null>`: `{ session: SessionRow; items: { id: string; item: Item; blockId: string; chapterId: string; itemGen: number }[]; answered: string[] /* itemIds con intento en esta sesión */; nextIndex: number /* primer índice de itemIds sin intento; = items.length si terminó */ }` (`null` si no existe). Ítems archivados desde que empezó la sesión se **omiten** de `items`.
  - `submitAnswer(db, input: { sessionId: string; itemId: string; attemptId: string; submission: Submission; durationMs: number }, ctx): Promise<AnswerResult>` con `AnswerResult = { status: 'saved' | 'duplicate'; correct: boolean | null; blockStatus: BlockStatus | null } `. Calcula `submissionOutcome(item, submission)` (si `ok:false` ⇒ **rechaza** sin guardar), construye el `Attempt` (`subjectId`, `chapterId`, `blockId`, `itemGen` y `tipo` del ítem **actual** en BD; `at = ctx.now`; `studyDay = studyDay(ctx.now, ctx.tz)`; `tz = ctx.tz`; `packVersion` = versión activa del capítulo; `schedulerVersion = studyConfig.schedulerVersion`; `durationMs` entero ≥ 0 (si no, rechaza) recortado a `studyConfig.maxAttemptMs` (3 600 000)) y llama a `recordAttempt`. `correct` = `outcome.correct` salvo `info`/`flashcard` (`null` para info; para flashcard `outcome.correct`). Un `duplicate` devuelve el mismo `correct` calculado. Falla de guardado ⇒ la promesa **rechaza** (la UI conserva la respuesta y ofrece «Reintentar» con el **mismo** `attemptId`).
  - `finishStudySession(db, sessionId, ctx): Promise<SessionSummary>`: idempotente; marca `endedAt` (si no estaba), y guarda `result` `{ correct, total }` (cuenta solo intentos **evaluables** de la sesión: sin `info`; para `exam` es lo que decide `passed`). Devuelve `SessionSummary` = `{ sessionId, kind, correct, total, blindSpotsCreated: number /* intentos con !correct && !dontKnow && confidence 'seguro' */, chapterChanges: { chapterId, titulo, before, after }[] /* solo los que cambian */, streak, secondsToday, goalReached, exam: { passed: boolean } | null }`. `after` se calcula con el estado actual (`allBlockStates` con todos los intentos); `before` = `percentBefore`.
  - `getSessionSummary(db, sessionId, ctx)`: igual que `finish…` pero **sin** modificar nada (sesión terminada o no).
- **`appStorage.ts`**: `getAppStorageStatus(db, nav: { storage?: StorageLike } | undefined)` reutiliza `storageStatus`/`requestPersistence` de M3-2; `getOpenSessions(db)`.
- Exporta todo desde `src/data/index.ts`. Constantes en `config.ts` (`studyConfig.maxAttemptMs`, textos fijos solo en la capa de UI).

### Proveedor de datos (`src/app/DataProvider.tsx`) y arranque seguro
Un contexto React (`useData()`) con `{ db, ctx(): { now, tz }, revision: number, bump(): void }`. Al montar abre la BD con `openStudyDb(dataConfig.dbName, { onVersionChange, onBlocked })` y muestra **pantallas de estado** según el resultado (cada una con un único botón y texto en español de España):
- cargando: «Abriendo tus datos…»;
- `ok` ⇒ renderiza la app;
- `version-newer`: «Hay una versión nueva de la app. Recarga para actualizar.» + botón «Recargar» (`location.reload()`);
- `blocked` / `onBlocked`: «Cierra las demás pestañas de la app.» + «Reintentar»;
- `migration-failed`: «No se ha podido actualizar tu base de datos. Tus datos no se han tocado.» + «Reintentar»;
- `unavailable`: «Este navegador no permite guardar datos. Prueba con Chrome.»;
- `onVersionChange` (otra pestaña actualizó): bloquea la interfaz con «La app se ha actualizado en otra ventana. Recarga.» + «Recargar».
`ctx()` usa el reloj **inyectable**: el proveedor recibe `clock?: () => Date` (por defecto `() => new Date()`) y `tz?: string` (por defecto `Intl.DateTimeFormat().resolvedOptions().timeZone`), para que los E2E puedan fijarlos. `bump()` incrementa `revision` (las pantallas la usan como dependencia para recargar tras escribir). Hook `useAsync(fn, deps)` que devuelve `{ status: 'loading' | 'ready' | 'error'; data; error }`, cancelando resultados obsoletos. El tema de Ajustes se aplica poniendo `data-theme="light"|"dark"` en `<html>` (o quitándolo para `system`) desde un efecto en el proveedor; añade en `global.css` las reglas `[data-theme]` coherentes con las variables ya existentes.
La **UI del proveedor** (≤ 150 líneas) no contiene lógica de negocio. Mantén `App.tsx` funcionando: envuelve lo existente con el proveedor y deja `HomeScreen`/`SettingsScreen` como están (se rehacen en M5-2).
