### 3.2 Función pura (`src/domain/progress/export.ts`)
```ts
export interface ProgressSession { id: string; kind: 'study' | 'review' | 'exam'; startedAt: string; endedAt: string | null }
export function buildProgressExport(input: {
  subjectId: string; catalog: Catalog; attempts: Attempt[]; sessions: ProgressSession[];
  itemStates: Map<string, ItemState>; now: string; tz: string;
}): ProgressExport
export function formatIsoWithOffset(instant: string, tz: string): string   // "2026-12-02T21:10:00+01:00"
export function shortText(item: Item): string                                  // enunciado_corto
export function progressFileName(subjectId: string, today: string): string      // progreso_<asignatura>_<AAAA-MM-DD>.json
```
Reglas (todas deterministas, sin `Date.now()`; entradas no mutadas; **solo** datos de `subjectId`):
1. `today = studyDay(now, tz)`. `exportado = formatIsoWithOffset(now, tz)` (hora **local** con desfase `±HH:MM`, segundos sin milisegundos; `UTC` ⇒ `+00:00`; verano/invierno correctos).
2. **Estado derivado**: `rebuildFromAttempts(attempts de la asignatura, catalog, today)` (no uses las cachés guardadas: el export debe ser reproducible desde el registro). `itemStates` se usa **solo** para `proximo_repaso` (cuando falte el estado de un ítem, ese ítem no aporta fecha).
3. `capitulos`: todos los de la asignatura por `numero` ascendente; `porcentaje = chapterPercent`; `bloques` en orden del paquete; **sin** bloques archivados; `estado` = status del dominio; `bloqueado` = `locked`; `dias_dominio` = `validDays` (vacío si perdió el dominio); `proximo_repaso` = el **menor** `due` entre los ítems evaluables, no archivados, con estado FSRS del bloque, convertido con `studyDay(due, tz)`; `null` si ninguno.
4. `sesiones`: solo las **terminadas** (`endedAt !== null`) de la asignatura **con al menos un intento**; `fecha` = `studyDay` del primer intento de la sesión (por `at`, luego `attemptId`); `minutos` = `Math.round(segundos / 6) / 10` donde `segundos` = suma de `durationMs` de **todos** sus intentos (incluidos `info`) / 1000; `preguntas` = nº de intentos **evaluables** (no `info`) de la sesión; `aciertos` = los `correct`; `tipo` = `estudio`/`repaso`/`examen` según `kind`. Orden ascendente por (`fecha`, `startedAt`, `id`); si hay más de 60, **las últimas 60**.
5. `puntos_ciegos` = `pendingBlindSpots` (ya filtra archivados/flashcards/generación); `fecha` = `since`; `enunciado_corto = shortText(item)`.
6. `fallos_recurrentes`: ítems evaluables no archivados con **≥ 2 intentos fallidos** (`!correct`, incluye «No lo sé» y flashcard «Otra vez») de la generación actual con `studyDay` en la ventana de **30 días de estudio** que termina en `today` (ambos incluidos: de `today − 29` a `today`); ordenados por `fallos` descendente y luego `item` ascendente.
7. `shortText(item)`: texto base = `enunciado` (o `anverso` en flashcard, `titulo` en info); sustituye cada `{{n}}` por `___`; colapsa espacios y saltos de línea en un espacio; `trim`; si supera 80 caracteres, corta a 80 y añade `…` (81 en total). No se elimina Markdown ni LaTeX.
8. La salida **siempre** valida contra `progressSchema` (la función lo comprueba y lanza `Error` con mensaje claro si no; una violación es un bug).

### 3.3 Servicio de datos (`src/data/progressExport.ts`)
`exportProgress(db, subjectId, ctx: DataContext): Promise<{ status: 'ok'; json: string; fileName: string } | { status: 'empty'; message: string } | { status: 'error'; message: string }>`: una transacción de lectura (catálogo, intentos de la asignatura, `sessions`, `itemState`), `buildProgressExport`, `JSON.stringify(…, null, 2)` + `\n`. Asignatura inexistente ⇒ `empty` («No encuentro esta asignatura.»). Una asignatura **sin intentos** exporta igualmente (sesiones vacías, % 0): `ok`. Cualquier excepción ⇒ `error` (nunca lanza). `fileName = progressFileName(subjectId, today)`. No escribe en la BD. Exporta desde `src/data/index.ts`.
